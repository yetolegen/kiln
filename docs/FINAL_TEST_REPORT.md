## Окружение и исходное состояние

- Windows, Node **24.21.0**, npm **11.19.0**; baseline `c8df5a7739b65263df40ba5abf176e250ab0ae09`.
- Ветка `final/motion-update`, исходный checkout чистый. Новых npm-зависимостей нет. Commit/push/deploy автоматически не выполнялись.
- Baseline: `npm ci`, typecheck, **321/321 unit**, build — успешно.
- Baseline Chromium: **25/27**. B6 ожидал устаревший текст, B2 не мог скачать WASM из CDN в sandbox. B2 с разрешённой сетью прошёл отдельно. Первоначальный runner остановлен после результатов из-за зависшего teardown; последующие browser-запуски выполнялись с разрешённой сетью/завершением процессов.

## Покрытие и разделение источников данных

- Unit: копии checkpoint, atomic rejection, монотонная revision, late/held input, отпускание, восстановление из glaze, сохранение времени/ошибок, firing immutability; реальные controller gestures с обеими ролями.
- DTO/render math: local anchors, CSS rectangle, поворот/nonuniform scale, виды и размеры деталей, ограничения штампов, миграции, все восемь глазурей, future storage и memory fallback.
- Codec: round-trip, whitelist, неизвестные версии, malformed/oversized/nonfinite данные, остановка распаковки при превышении 64 КиБ. Измеренные fixtures: **156** символов для простой формы, **467** для примера с 6 деталями и 8 штампами; это не worst-case для всех комбинаций.
- Browser mock: реальные DOM, dwell, отображение, редактор, галерея и ссылки; форму/позы задаёт MockCore. Такие тесты не доказывают распознавание настоящей камеры.
- Browser real pipeline: в `timing.pw.ts` и `finalPipeline.pw.ts` заменён только источник landmarks; FeatureExtractor, контроллер, recognizer, UI и браузерные адаптеры настоящие. Камера Chromium — синтетическая.
- Production smoke: отдельный собранный bundle, без dev mock. Проверяется отдельно от Vite dev и физической камеры.

## Найденные ошибки и исправления

Полный интеграционный прогон первоначально дал 17/33 успешных проверок. Среди причин: отсутствующие hand hit-areas после fade-in, переполнение новых landscape-кнопок, перекрытие PNG карточкой, повторное перелистывание под удержанием, старые утверждения UI и ранние клавиши mock до загрузки приложения. Они исправлены; повторные targeted результаты и финальный gate записываются ниже. Дополнительно исправлены возврат preview после tracking loss и замедление software WebGL адаптивным разрешением. Безопасные пороги свежести не ослаблялись.

## Обязательный физический проход перед выступлением

- [ ] Записать утверждённые commit/build URL, устройство, браузер и освещение. Публичный адрес `https://kiln-delta-rose.vercel.app/` **не обновлялся этой задачей**.
- [ ] Разрешить настоящую камеру; пройти калибровку и меню ладонью.
- [ ] Проверить исходное narrowing, внешнее widening, подъём, indentation, opening, compression и внутреннее расширение; поменять активную/поддерживающую руку.
- [ ] Сохранить точку, реально испортить глину, прочитать причину, восстановить. Удержание/старое положение не должны снова деформировать её.
- [ ] Проверить повторный save с отменой замены, restore до оформления/из оформления, reload-resume.
- [ ] Щипком плавно осмотреть, отпустить, потерять руку, вернуться новым захватом; поворот не должен лепить или нажимать UI.
- [ ] Разместить/изменить/переместить/отменить/удалить деталь; поставить штамп, изменить цвет/поворот. Повторить на другом боку после поворота.
- [ ] Обжечь, открыть выбранную работу с полки, вернуться на ту же страницу, выгрузить PNG.
- [ ] Открыть ссылку в чистом браузере без камеры; затем отдельно разрешить/отклонить optional camera.
- [ ] Пройти пять новых модулей, повторить/пропустить. Личная полка/точка/рекорды должны сохраниться.
- [ ] Проверить portrait/landscape и производительность на телефоне. Синтетические screenshots — не подтверждение физического телефона.

Дополнительные найденные ошибки: модульная подсказка перекрывала оформление; непрерывный щипок мог активировать повтор в новом окне; неподвижный крупный 3D-вид перерисовывался слишком дорого. Исправлены расположение панелей, release-gate на границе окна и кэш статичного кадра/теней. PNG теперь получает отдельную камеру по bounds всего изделия. При потере WebGL недоступные 3D-кнопки отключаются; оформление сохраняется, неполный PNG с отсутствующим декором не выдаётся за готовый.

В одном browser helper открытие modal ошибочно ожидалось по прогрессу старой кнопки: реальный UI уже успешно открыл окно. Проверка исправлена на наблюдение перехода. Portrait-fixture теперь использует одну UI-руку: фиксированная вторая mock-ладонь прежде сама выбирала меню. Исходные двухручные проверки widening сохранены.


### Полный повтор и производительность

Первый полный повтор после интеграции: **31 passed, 1 failed, 7 not run** (остановка на первом сбое). `finalPipeline.pw.ts` прервался при входе в меню: software graphics снова вызвала разрыв свежих наблюдений. Ограничения input не ослаблялись; адаптивное уменьшение разрешения теперь охватывает и карту теней, а не только цветовой буфер. Повтор этой проверки входит в финальный gate. Предыдущий отдельный полный hands-only маршрут уже проходил, но этот факт не подменяет результат полного повтора.


Дальнейшая диагностика уточнила причину: `REACQUIRE_MS` равен **150 мс**, а отдельные интервалы synthetic camera составляли около **153 мс**. Поэтому новый trackId сбрасывал dwell ещё до 200-мс порога устаревания. Адаптивный renderer теперь уменьшает разрешение и тени заранее, ориентируясь на 45-мс кадр и запас для video callbacks. Оба исходных tracking-порога сохранены. После исправления `--grep 'real pipeline' --repeat-each=3 --max-failures=1` дал **3/3** успешных сквозных прохода. Временная обёртка DwellController удалена.

Отдельно исправлена гонка тестового helper: проверка существования кнопки и получение её rect выполняются одним browser evaluation, поэтому переход экрана между двумя измерениями не выдаётся за дефект dwell. Повторный полный прогон до этого уточнения тоже остановился с 31 passed / 1 failed / 7 not run; эти промежуточные запуски не считаются финальным успехом.

Финальный разбор данных добавил регрессии, которые сначала упали и затем прошли: массив вместо строкового checkpoint stage/cause; пустой session id; причина bottomHole без отверстия; потеря счётчика ошибок оформления при restore. Reader теперь строго проверяет типы, а restore сохраняет историю оформления текущей попытки. Старый отсутствующий pinch больше не блокирует новую pointing-руку. Все **355 unit-тестов** проходят.

### Финальный gate и production smoke

Полный Chromium-прогон завершён: **39/39**, без пропущенных проверок. В него вошёл реальный synthetic-landmark маршрут (46,2 с), все новые модули, старый урок, мобильные размеры и проверки свежести.

После просмотра screenshots найдена отдельная ошибка: переход открытого viewer с desktop в portrait менял aspect, но не расстояние камеры, поэтому сосуд обрезался по бокам. Добавлен regression: он сначала упал (Z остался 5,8 вместо ожидаемых ≈12,55). `scene.setProjection` теперь сохраняет угол и относительный zoom, пересчитывая расстояние и лимит камеры. Повтор в production Chromium, Firefox и WebKit прошёл; production build после исправления также успешен. Этот последний UI-fix проверяется отдельным набором затронутых browser-маршрутов, а не выдаётся за часть предшествующего полного запуска.

Первый cross-browser запуск дал Firefox pass / WebKit fail из-за самого fixture: Windows WebKit не имел `navigator.mediaDevices`, который тест пытался перезаписать. Probe теперь корректно создаёт отсутствующий API и отдельно проверяет отсутствие его вызова; повтор **2/2**. Это не подтверждение поддержки настоящей камеры WebKit на этом компьютере.

Команда запуска preview: `npm run preview -- --host 127.0.0.1 --port 4173 --strictPort`. В PowerShell переменная задавалась как `$env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:4173'`. Проверялся локальный production bundle; публичный deploy не изменён. Автоматический Chromium использовал fake video device, а не физические руки.

Последний targeted Chromium-повтор после resize-fix: **6/6**, 1,4 минуты. Portrait screenshot просмотрен: сосуд целиком помещается в viewport, органы управления доступны. Финальный typecheck и `git diff --check` успешны; bundle не содержит dev mock.

Diff-аудит подтвердил неизменность `tracking/gestures.ts`, `tracking/externalWiden.ts`, `engine/clay.ts`, `config.ts`, `ui/tutorial.ts`, `ui/tutorialGeometry.ts`, исходных `externalCompression.test.ts` / `externalWiden.test.ts` и полных разделов widening обеих README. Проверялись содержимое и окончания строк; коэффициенты, жест, учебная цель и порядок сохранены. HEAD всё ещё `c8df5a7739b65263df40ba5abf176e250ab0ae09`.
